# 02. Keep the literal types of the public configs

**Date**: 2026-11-07

**Problem**:

- A consumer's IDE lists the rule names of a config, eg. `tsConfig.rules`, only
  while its type keeps them

**Solution**:

- Type each config in `src/configs/` and `src/rules/` with `@type {const}` and
  `@satisfies {import("eslint").Linter.Config}`

**Rejected**:

- `@type {import("eslint").Linter.Config}`: it widens every key

**Acknowledgments**:

- The literal types in `dist/types/` name each plugin's types, eg.
  `JsdocPlugin`. A consumer that checks its `eslint.config.js` with
  `declaration: true` fails with TS2883 when that plugin is installed in a
  nested `node_modules`
  - That consumer sets `"declaration": false` for the check
