# 01. Allow a leading `_` on private names

**Date**: 2026-10-21

**Problem**:

- A leading `_` marks a private name, eg. `_parseRow`, `_cache`
  - `no-underscore-dangle` rejects it
  - `naming-convention` allows it only in its `default` selector. A boolean or a
    global `const` selector replaces the `default` options instead of merging
    them

**Solution**:

- Allow a leading `_` in both rules
