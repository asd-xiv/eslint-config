### It forbids the `style` prop

```tsx
// Before
<p style={{ marginTop: 8 }}>Saved</p>

// After, with `.note { margin-top: 8px; }` in `note.module.css`
<p className={css["note"]}>Saved</p>

// After, for a value known only at runtime
// eslint-disable-next-line react/forbid-dom-props -- the bar follows the upload
<div style={{ width: `${percent}%` }} />
```

**If unchanged**:

- ESLint reports `Prop "style" is forbidden on DOM Nodes`
- On a component, ESLint reports `Prop "style" is forbidden on Components`

**Reason**:

- An inline style beats every class in the cascade
- An inline style cannot use a media query or a state such as `:hover`

### It forbids `forwardRef`

```tsx
// Before
const Input = forwardRef<HTMLInputElement, InputProps>((props, ref) => (
  <input {...props} ref={ref} />
))

// After
const Input: FC<InputProps> = ({ ref, ...props }) => (
  <input {...props} ref={ref} />
)
```

**If unchanged**:

- ESLint reports
  ``'forwardRef' import from 'react' is restricted. Read `ref` from the props, as React 19 passes it``

**Reason**:

- React 19 passes `ref` as a prop
  ([React 19](https://react.dev/blog/2024/12/05/react-19#ref-as-a-prop))
- React plans to deprecate and remove `forwardRef`
  ([React 19](https://react.dev/blog/2024/12/05/react-19#ref-as-a-prop))

### It reports the faults of the jsx-a11y recommended rules

```tsx
// Before
<div onClick={handleOpen}>Open</div>

// After
<button type="button" onClick={handleOpen}>
  Open
</button>
```

**If unchanged**:

- ESLint reports
  `Visible, non-interactive elements with click handlers must have at least one keyboard listener.`
- ESLint reports
  `Avoid non-native interactive elements. If using native HTML is not possible, add an appropriate role and support for tabbing, mouse, keyboard, and touch inputs to an interactive content element.`

**Reason**:

- A `<div>` with a click handler takes no focus and no Enter key, so a keyboard
  user cannot open it

### An anchor in a `render` prop needs a disable comment

```tsx
// Before
<Button render={<a href="/docs" />}>Docs</Button>

// After
// eslint-disable-next-line jsx-a11y/anchor-has-content -- Base UI fills the anchor with the children
<Button render={<a href="/docs" />}>Docs</Button>
```

**If unchanged**:

- ESLint reports
  `Anchors must have content and the content must be accessible by a screen reader.`

**Reason**:

- `jsx-a11y/anchor-has-content` reads the anchor alone, and Base UI gives it the
  children only at runtime
- The rule has no option to skip such an anchor: its one option, `components`,
  only adds elements to check
  ([anchor-has-content](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y/blob/main/docs/rules/anchor-has-content.md))
